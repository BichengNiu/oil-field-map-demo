# 四海域历史接入

## 已核实的来源与尚缺的交付

2026-10-06 查阅 [VesselFinder 官方历史服务](https://www.vesselfinder.com/historical-ais-data)：历史 AIS 自 2009 年起；支持自定义区域的轨迹及基于地理多边形的进出事件 CSV/XLS 交付，须询价并由供应商确认实际可用性。公开示例只是图片，不是可下载的完整历史数据。目前本项目没有商业历史凭据，也没有收到四海域授权事件文件，**尚未导入真实四海域历史**。

本次实现的是授权交付文件到事件库、地图卡和报告卡的完整接入路径。`SEA_HISTORY_BUNDLE_URL` 是用户或供应商提供的交付 ZIP 地址，不是 VesselFinder 官方 API；不能仅配置 AISStream 实时密钥就获得历史数据。不能以示例、公开局部样本或海峡计数填补四海域统计。

请向供应商申请：波斯湾、红海、阿曼湾、亚丁湾四个固定地理多边形的**所有确认进入事件**，包括同船重复进入；需要卫星与岸基覆盖说明、事件检测规则、边界版本，以及逐海域逐日的完整性声明和独立事件总数。第一批建议包含 2025-09-01 至最新完整日的历史，之后每日更新。四个区域的实际数据覆盖、事件识别质量和授权使用范围均需供应商确认；供应商网页的全球历史介绍不是四海域无缺报保证。

只要提供同一来源、同一边界口径的上周、前周、本月、上月同期及去年同期完整日期，就可计算当前卡。2026-10-06 的上周是 09-28 至 10-04，前周是 09-21 至 09-27；若最新完整日为 10-05，本月比较 10-01 至 10-05、09-01 至 09-05、2025-10-01 至 10-05。

## 交付格式

每个 ZIP 根目录各包含一个 `manifest.json`、`events.csv`、`coverage.csv`。可在数据下载页下载空模板；模板不含假事件或假的零值覆盖。

`manifest.json` 必填：

| 字段 | 要求 |
| --- | --- |
| schema_version | 整数 1 |
| source | 真实供应商名称；所有批次一致 |
| source_url | 供应商 HTTPS 来源页 |
| definition_id | 供应商四海域边界及事件判定规则的固定版本；建议使用约定多边形与规则的 SHA256 |
| event_basis | `sea_entry` |
| timezone | `Asia/Shanghai`，所有统计日期统一按此时区 |
| seas | 四项：波斯湾、红海、阿曼湾、亚丁湾 |

`events.csv` 字段：`sea,mmsi,entered_at`。`entered_at` 是真实进入事件时间，必须包含 UTC `Z` 或明确时区偏移。九位 MMSI 按文本保存。供应商报告只选自定义海域的 Arrival/Enter 事件，按明确字段映射为这三个字段；Departure、状态变化、普通港口 Arrival 不导入。没有核实供应商实际 CSV 表头前，不自动猜测转换。

每个不同的 `(sea,mmsi,entered_at)` 计一艘次；重复上传和重复行不增计，同船不同时间进入、进入不同海域分别计数。供应商须保证单次进入不会被重复识别为多个相近时间事件；程序不会用任意时间间隔合并真实再次进入。

`coverage.csv` 字段：`sea,date,status,event_count`。日期是上海时区的已结束自然日，`status` 必须是 `complete`，`event_count` 是供应商确认的该日进入事件数。必须逐海域逐日提供；确认完整且无事件的一天填写 0，未覆盖日期不要填 0。每个覆盖日的数量必须与去除重复后的事件文件一致；不能从自己截取的不完整事件文件反推“完整”。若供应商按 UTC 日声明覆盖，须取得涵盖整个上海自然日的原始覆盖区间，再换算声明和计数；不能直接改日期标签。

程序会拒绝无覆盖、未知海域、错误时间、数量不一致、当前未结束日期及不同供应商/边界混合批次。每批完整海域日原子替换旧交付；其他日期保留。缺少任何一个海域日时，该比较窗口保持未知；真实零保留为 0，基期为 0 的增长率保持未知。

## 接入方式

服务器环境变量或 Streamlit Secrets 中配置：

- `SEA_HISTORY_ARCHIVE_PATH`：持久磁盘上的 SQLite 路径。缺省为项目下 `runtime/sea-history.sqlite3`；无持久盘的部署重启会丢失此库，应保存原始授权 ZIP 并通过交付源重新导入。初次文件要包括所需全部比较历史。
- `SEA_HISTORY_BUNDLE_PATH`：授权 ZIP 本地路径；或 `SEA_HISTORY_BUNDLE_URL`：授权交付 ZIP 的 HTTPS 地址，二者只选一个。
- `SEA_HISTORY_BEARER_TOKEN`：交付地址需要 Bearer 授权时配置。带签名 URL 本身也属于秘密。密钥不会发给浏览器或写入版本库；不跟随 HTTP 跳转。
- `SEA_HISTORY_IMPORT_TOKEN`：可选的网页管理员导入口令。未配置时网页不允许写入共享档案；服务器交付源仍可读取。

地图/报告读取时最多每 15 分钟同步配置交付并共用事件库；“数据下载”页可立即刷新。更新失败会保留原档案并显示错误，不把旧数据改为零。单次 ZIP 及解压后的三个文件总计最大 50MB，大文件按完整海域日拆分批次。

也可在服务器手动导入：

```bash
python -m monitor.vessels.sea_history /path/to/authorized-delivery.zip --database /persistent-data/sea-history.sqlite3
```

网页导入在“数据下载 → 海域历史数据 → 接入历史进出事件”，输入管理员导入口令并上传 ZIP。成功后清除卡片缓存；地图及报告立即共用该档案。月份比较取本月四海域共同的最新完整日；自然周始终以当前日期为锚，周一不会因日资料只到周日而错退一周。完整日期覆盖可在此页查看，卡片不添加长口径说明。

## 排除的来源

- [AISStream](https://aisstream.io/documentation) 是实时消息源，现有本地归档不是全域完整历史事件，也没有去年同期。
- [公开 Hormuz API](https://github.com/marco83g-dotcom/hormuz-api) 只覆盖波斯湾/阿曼湾部分区域间的推断穿越，不覆盖红海、亚丁湾；不能替代四海域进入事件。
- [Datalastic 历史服务](https://docs.datalastic.com/) 可查询历史轨迹和区域报告，但船只出现记录或去重船只数需要完整轨迹及固定边界处理后才是进入事件，不能直接作为艘次。
- 项目已有近迪拜 2026-03/04 的公开 AIS 样本缺红海、亚丁湾及比较期，仅用于原始样本研究。
- PortWatch 海峡日统计可用于通道卡，其边界及事件对象与四海域卡不同。
